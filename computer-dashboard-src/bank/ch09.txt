#20 p348 a371

K: d

#31 p349 a373
Q: Why is the following statement erroneous?
```
SELECT dept_name, ID, avg(salary)
FROM instructor
GROUP BY dept_name;
```
a) ID is selected but is neither in the GROUP BY clause nor inside an aggregate function
b) Group by clause is not valid in this query
c) Avg(salary) should not be selected
d) None
K: a
X: With GROUP BY, every column in the SELECT list must either be a grouping column or appear inside an aggregate function. `dept_name` is grouped and `salary` is aggregated, but `ID` is neither, so the query is invalid.
S: SELECT list with GROUP BY → grouped column or aggregate only.
N: The book's option (a) read "Dept_id should not be used in group by clause". The query does not use dept_id, and grouping by dept_name is valid. The book's own explanation gives the real reason (an attribute outside the GROUP BY must be aggregated), so option (a) has been reworded to state it.

#41 p351 a374
Q: When is the "ROLLUP" operator for expressions or columns within a "GROUP BY" clause used?
a) To find the groups that make up the subtotal in a row
b) To create group-wise grand totals for the groups indicated in a GROUP BY clause
c) To group expressions or columns specified in a GROUP BY clause in one direction, from right to left, for computing the subtotals
d) To produce a cross-tabular report for computing subtotals by grouping phrases or columns given within a GROUP BY clause in all available directions
K: c
X: `ROLLUP(a, b, c)` produces subtotals by removing columns one at a time from right to left: (a,b,c), (a,b), (a), then the grand total. `CUBE` (option d) gives subtotals for every combination, in all directions.
