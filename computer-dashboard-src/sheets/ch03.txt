## 60-second recap
- ★ **Von Neumann:** program and data share one memory (stored-program concept) → the "von Neumann bottleneck". Harvard = separate memories.
- ★ **Registers:** PC = next address · IR = current instruction · MAR = address · MDR/MBR = data · accumulator = ALU result.
- ★ **Cache:** SRAM between CPU and RAM, checked first, smaller than RAM, measured by **hit ratio** (miss rate = 1 − hit rate).
- ★ **Non-volatile:** ROM, PROM (write once), EPROM (UV), EEPROM, flash. **Volatile:** DRAM, SRAM.
- ★ **Address lines** ↔ number of locations (2ⁿ); **data lines** ↔ bits per location.
- ★ **MMU** maps virtual → physical addresses (paging, TLB). Virtual memory = bigger address space, not bigger disk.

## Functional units (von Neumann model)
- ★ **Input unit → Memory unit ↔ CPU (ALU + CU + registers) → Output unit.** Data processing is done by the **CPU with memory**.
- **Von Neumann architecture:** program and data share one memory and one bus (the stored-program concept), which creates the "von Neumann bottleneck". **Harvard architecture:** separate instruction and data memories.
- **FPU** (floating-point unit / math co-processor) does real-number arithmetic; **GPU** handles parallel graphics maths.
- **Clock generator** paces every step; the **control unit** sequences each instruction on those pulses.
- **Scheduler / dispatcher** decides which process goes next (the OS scheduler allocates CPU time: FCFS, SJF, priority, round robin).

## Registers (fastest storage, inside the CPU)
- **PC (program counter):** address of the **next** instruction, incremented after each fetch. **IR (instruction register):** the instruction being decoded.
- **MAR:** address to read or write. **MDR/MBR:** the data coming from or going to memory.
- ★ **Accumulator (AC):** holds one ALU operand and receives the result. **Flag / status register:** zero, carry, sign, overflow bits.
- **Stack pointer:** top of the stack (subroutine calls and interrupts).
- ★ Registers and cache are **internal processor memory**; ROM and optical discs are not.

## Cache memory
- ★ Small, very fast **SRAM** between CPU and RAM. The CPU checks the **cache first**; a hit avoids a slow RAM trip.
- ★ Speed order: **registers > cache > RAM**, and the cache is always **smaller than RAM**.
- ★ Effectiveness is measured by the **hit ratio** = hits ÷ (hits + misses). Levels: L1 (per core, smallest) < L2 < L3 (shared). L1 is split into instruction and data caches.
- Works because of **locality of reference**: temporal (reused soon) and spatial (neighbours used soon).
- ★ **Associative (content-addressable) memory:** looked up by content — the data itself is the address. Used in cache tags and TLBs.

## Memory types and chips
- ★ **Volatile:** DRAM, SRAM. **Non-volatile:** ROM, PROM, EPROM, EEPROM, flash. Of DRAM, SRAM and EPROM, only **EPROM** is non-volatile.
- ★ **PROM** = written **once**; **ROM** contents cannot be erased by the user.
- ★ **Flash** suits phones, cameras and music players (microSD cards). A **flip-flop** stores 1 bit and is a sequential circuit.
- **Secondary memory** is permanent storage.
- ★ **Address lines:** $2^n$ locations need **n** lines (1024 → 10). **Data lines = bits per location** (2-byte words → **16** lines).
- ★ Capacity = locations × word size. 1 GB = 1024 MB = **1024 × 1024 KB**.

## Memory management
- **MMU** translates virtual (logical) addresses into physical addresses using page tables; the **TLB** caches recent translations.
- ★ **Paging:** memory in fixed-size **frames**, programs in **pages**; it maps virtual → physical addresses.
- ★ **Virtual memory:** a large address space beyond physical RAM and efficient sharing of RAM among users. It does **not** provide a larger secondary memory.
- **Segmentation:** variable-size logical blocks (code, data, stack).
- Allocation decisions are made by the **OS memory manager**; the MMU enforces them in hardware.

## Interface and conversion units
- **BIU (bus interface unit):** connects the CPU to the system bus and prefetches instructions (queue); the **EU** executes them (8086).
- **Memory controller:** RAM reads, writes and refresh. **I/O controller / device controller:** runs a peripheral, with DMA for block transfers.
- ★ **ADC** turns analog into digital (microphone → PC); **DAC** turns digital into analog (PC → speaker). A **modem** does both (MOdulator–DEModulator).
- **Pipelining:** overlaps fetch/decode/execute of several instructions, like an assembly line, raising throughput.
- **Decoder:** n inputs → $2^n$ output lines; selects memory chips and decodes instructions.
- ★ Interface units: **NIC** (network, 48-bit MAC address), sound, graphics, USB, SATA, Wi-Fi (**IEEE 802.11**; 802.11ad fastest), Bluetooth, smart-card, touch, stylus, joystick.

## ★ Most-tested facts
- 1024 locations × 8 bits → **10 address lines**; a 2048 × 2-byte chip → **16 data lines**.
- Associative memory → **content-addressable; the data itself acts as the address**.
- Internal processor memory → **cache + registers**; the CPU looks first in → **cache**.
- Written only once → **PROM**; non-volatile among DRAM/SRAM/EPROM → **EPROM only**.
- Cache: "larger than RAM" ✗, "faster than RAM but slower than registers" ✓, "measured by hit rate" ✓.
- Virtual memory: large address space ✓, sharing RAM ✓, "large secondary memory" ✗.
- The MAC address is the hardware (physical) address; the IP address is logical.

## Traps to avoid
- **Address lines ↔ number of locations; data lines ↔ word width.** Don't mix them up.
- The **PC holds an address**, not an instruction; the IR holds the instruction.
- Virtual memory **enlarges the address space**; it does not add disk space and is slower than RAM.
- If the OS is not among the options for "allocates memory", pick the **MMU**; if it is, pick the **OS**.
