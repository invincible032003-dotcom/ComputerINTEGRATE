## Generations of languages
- **1GL machine language:** binary, machine-dependent, fastest, error-prone, needs no translator.
- **2GL assembly:** mnemonics (MOV, ADD) and labels. It needs an **assembler** and is still machine-dependent (a low-level language).
- **3GL high-level:** English-like, portable, procedural (FORTRAN, COBOL, C, Pascal, BASIC, Java). Needs a compiler or interpreter.
- **4GL:** non-procedural, database, query and report oriented (**SQL**, report generators, form builders). Means rapid application development.
- **5GL:** constraint and logic based, used for AI (**Prolog**, Mercury, OPS5).
- Abstraction rises and hardware dependence falls from 1GL to 5GL.

## Translators and the build chain
- **Assembler:** assembly → machine code. **Compiler:** the whole HLL program → object code. **Interpreter:** translates and runs **line by line** (ISS 2018).
- A compiler reports all syntax errors after a full scan and makes a fast executable. An interpreter stops at the first error, runs more slowly and is needed at every run.
- **Compiler phases:** lexical (→ **tokens**, ISS 2021) → syntax (parse tree) → semantic → intermediate code → optimisation → code generation.
- **Linker:** combines object files and **library routines** (e.g. `exp()` from the math library, ISS 2023) into one executable (ISS 2019, 2025).
- **Loader:** puts the executable into RAM, allocates memory and starts it. **Relocation** adjusts addresses to the load location.
- **Absolute loader:** the assembler/programmer does allocation, linking and relocation. The loader only loads (ISS 2026: allocation is done by the assembler).
- **Dynamic linking:** libraries (`.dll`, `.so`) are linked at load or run time and shared in memory.

## Errors
- **Syntax (grammatical) error:** caught by the compiler. A compiler diagnoses **grammatical errors only** (ISS 2018).
- **Logical error:** the program runs but gives wrong results. A program can run successfully despite one (ISS 2018).
- **Run-time error:** crashes during execution (divide by zero, invalid memory access).

## Software classes
- **System software:** OS, device drivers, translators, linkers, loaders, utilities. A **word processor is NOT system software** (ISS 2021).
- **Utility software:** antivirus (ISS 2019), backup, compression, disk cleanup, **encryption, data recovery** (ISS 2024 counted four utility tasks; search-and-replace is an editor feature).
- **Firmware:** software in ROM, such as the BIOS (ISS 2018). **Middleware:** software connecting applications to each other or to databases.
- **Runtime environment** (JVM, CLR): manages memory allocation, **garbage collection** and other run-time tasks (ISS 2025).

## Languages ISS likes
- **C:** Dennis Ritchie, 1972, Bell Labs. **UNIX is written in C** (ISS 2026).
- **C#:** Microsoft, for the **.NET** platform (ISS 2020). **Java:** Sun (Gosling), "write once run anywhere" via bytecode and the JVM.
- **Python:** interpreted, **platform-independent**, used for web apps (ISS 2026). The statement "Python is platform-dependent" is false (ISS 2021).
- Classification pairs: high/low level · procedural/object-oriented · compiled/interpreted · imperative (how) / declarative (what).

## PYQ: What ISS asked (2018–2026)
- **2018 Q70** Interpreter translates and executes simultaneously. **2018 Q76** Compiler → grammatical errors only.
- **2018 Q78** Runs despite a **logical error**. **2018 Q80** Low-level → **machine language**.
- **2019 Q44** Joins object code of all modules → **linker**. **2021 Q80** Lexical analyser output → **tokens**.
- **2024 Q47** Both translate HLL ✓; interpreter translates the whole program first ✗ → **I only**.
- **2025 Q72** Linker's purpose → **combine object files and libraries into an executable**.

## Traps to avoid
- An **interpreter produces no object file**, so a compiled program runs without its compiler but an interpreted one needs the interpreter every time.
- **Linker ≠ loader:** the linker joins files, the loader puts the result in memory.
- 4GL = SQL (database); 5GL = Prolog (AI). Don't swap them.
